# Dagster on AKS → Azure Databricks POC

Proof of concept: Dagster (OSS, Helm on AKS) orchestrates Azure Databricks.
One SDP pipeline ingests an API into a `bronze` table; one dbt model builds `silver`.
Two environments (stage, prod); CI promotes main → stage → prod.

Read `docs/guide.md` first. It is the source of truth for setup steps and progress (✅ = done).

## Non-negotiables
- **No public ingress.** Dagster UI is ClusterIP only, reached via `kubectl port-forward`. Never create an Ingress or `type: LoadBalancer` Service for Dagster.
- **No secrets in the repo.** Secrets live in Azure Key Vault and are mounted via the Secrets Store CSI driver. GitHub holds IDs only (tenant, subscription, client ID), never secrets.
- **Everything is parametrized by `env`.** Workspace URL, catalog, namespace, Postgres DB name, image tag all come from tfvars / Helm values / bundle targets. Never hardcode an environment-specific value in `dagster/`, `dbt/`, or `databricks/src/`.
- **Promote, don't rebuild.** Prod gets the exact image digest and bundle that passed on stage.
- **Nothing unique to one person or account is committed.** The repo is a blueprint others will clone. No personal handles, subscription/tenant IDs, IPs or org names in tracked files. Per-user values live in the git-ignored `.env`, generated by `scripts/setup-env.sh` (all keys scaffolded, see `.env.example`). Committed files reference them via `TF_VAR_*` (Terraform), `--set` (Helm, via `scripts/helm-upgrade.sh`), `env_var()` (dbt), or `DATABRICKS_HOST` (bundle, via `scripts/bundle-deploy.sh`). After each Terraform apply, run `scripts/setup-env.sh collect-tf <stack>` to capture outputs. The `justfile` loads `.env` automatically (`just --list` shows all commands); fallback `source scripts/load-env.sh`. Claude's shell has no `just`, so load it explicitly (`source scripts/load-env.sh`) before Terraform or any command that needs it; CI uses GitHub repo variables.
- **Lean.** Build only what `docs/costs.md` lists. No VPN, no private endpoints, no Premium ACR, no second AKS cluster. If something seems missing, check `docs/decisions.md` before adding it.

## Rules for Claude Code
- Before any step that needs the Azure portal, Databricks account console, a browser login, a trial acceptance, or pasting a credential: **stop and hand it to the user** with exact click-by-click instructions and tell them what value(s) to bring back.
- Never commit or push directly to `main` (no branch protection, so this is a convention). Work on a branch and merge via PR.
- Never run `terraform apply` or `helm upgrade` against **prod** without the user's explicit go-ahead in the same session.
- After completing a guide step, mark it ✅ in `docs/guide.md` and update `## Current state` below.
- Prefer `az`, `terraform`, `helm`, `databricks`, `dbt`, `dg` CLIs over ad-hoc REST calls or SDK scripts.
- Pin versions. Use `uv` for Python. Use the versions in `.tool-versions`.
- When something fails, read the error, fix the root cause, and note any gotcha in the guide step.

## Key commands
```
source scripts/load-env.sh                 # load .env (just does this automatically)
scripts/setup-env.sh                       # detect Phase 0 values, scaffold all future keys
scripts/setup-env.sh collect-tf shared     # capture terraform outputs into .env
scripts/setup-env.sh collect-bundle stage  # capture pipeline ID after bundle deploy
terraform -chdir=infra/env init && terraform -chdir=infra/env plan -var-file=stage.tfvars
scripts/helm-upgrade.sh stage              # helm upgrade with per-user values from .env
scripts/bundle-deploy.sh stage             # bundle deploy with DATABRICKS_HOST from .env
dbt build --target stage                   # from dbt/ (reads env vars via profiles.yml)
dg check defs                              # from dagster/
scripts/port-forward.sh stage              # Dagster UI at http://localhost:3000
scripts/stop.sh / scripts/start.sh         # cost control (pause — floor ~$35-40/mo)
scripts/teardown.sh / scripts/standup.sh   # cost control (delete AKS — floor ~$15/mo)
scripts/destroy-all.sh                     # destroy everything, start fresh
scripts/verify.sh 0                        # verify phase 0 is complete (0-5)
```
